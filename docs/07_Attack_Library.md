## Attack Patterns (8 distinct)

Each pattern is a small Python block that the
`scripts/gen_phase7_implementations.py` generator inlines into
the stub's `execute()` method.

### 1. `framing_or_replay_inject` (transport × S/T/R/I/D/E)

Smuggles a payload marker into the framing bytes / replay surface
of the transport. The source connector invokes `echo` with a
marker-carrying argument set; the harness's Evaluator checks
whether the marker surfaces in the sink's view of the call.

### 2. `session_fixation` (session × S/T/R/I/D/E)

Forces a fixed session ID on the source connector and inspects
whether the sink's session store returns the source's payload
marker. Mirrors Phase-5 misuse case MC-2.

### 3. `tool_shadow_inject` (namespace × S/T/R/I/D/E)

Invokes a tool whose name shadows a built-in (e.g.
`shadow_set_env`) and reads a resource whose URI is shaped by
the squatted name. Mirrors Phase-5 misuse case MC-1.

### 4. `result_smuggle_or_inject` (tool × S/T/R/I/D/E)

Indirect prompt injection: source connector invokes `echo` with
a payload carrying a prompt-like instruction; sink connector
reads a resource whose contents include the same marker. Cross-
boundary (tool ↔ resource).

### 5. `path_traversal_uri` (resource × S/T/R/I/D/E)

Path traversal attack: source connector reads a URI with `..`
traversal and percent-encoded slashes (`%2F`); sink connector
checks whether the traversal surfaced the marker. Mirrors
Phase-5 misuse case MC-3.

### 6. `scratchpad_or_memory_leak` (memory × S/T/R/I/D/E)

Source writes a value to a scratchpad keyed by name only (no
`tenant_id`); sink reads the same key. Mirrors Phase-2 confused-
deputy concept.

### 7. `cache_key_collision` (cache × T/R/I/D/E)

Both connectors attempt to read the same cache entry keyed by
`(tool_name, args_hash)`; the attack succeeds if the sink
returns the source's payload. Mirrors Phase-5 misuse case MC-4.

### 8. `token_replay_or_misuse` (auth × S/T/R/I/D/E)

Source connector invokes a tool that performs an SSRF-style
fetch carrying the original Authorization header; sink connector
reads a resource to detect whether the token surfaced.

## Cross-Cutting Attacks

### `ResultInjectionAttack` (`A-TOL-001`)

Indirect prompt injection via tool result content. Touches both
the **tool** and **resource** boundaries. Implements
`A-TOL-001`, `A-RES-006`, and `A-RES-007` simultaneously.
CVSS:3.1: `AV:N/AC:L/PR:L/UI:R/S:C/C:H/I:H/A:N`.

### `GrammarFuzzAttack` (`A-FUZZ-001`)

Grammar-aware fuzzing harness adapted from LSPFuzz (Zhu et al.
2025). Generates N well-formed-but-malicious JSON-RPC envelopes
with mutated parameter shapes. Phase 9 will exercise this
against the reference servers.

## Pytest Reproducibility

```bash
pytest tests/test_attack_library.py -v
```

Expected output (truncated):

```
.................................................................
204 passed in 0.12s
```

The test file parametrizes over every registered id:

- `test_minimum_attack_count` — asserts ≥25.
- `test_every_boundary_has_at_least_one_attack` — asserts each
  of the 8 `Boundary` enum values has ≥1 attack.
- `test_attack_id_format` — id matches `A-PREFIX-NNN`.
- `test_attack_has_cvss` — every class has a CVSS vector
  (attribute or docstring).
- `test_attack_subclasses_attack_base` — every class subclasses
  `attacks.base.Attack`.
- `test_attack_instantiable` — every class can be instantiated.
- `test_attack_execute_runs` — one representative attack runs
  end-to-end.
- `test_no_duplicate_ids` — no id collisions.
